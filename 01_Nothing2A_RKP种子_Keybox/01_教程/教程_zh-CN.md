# Nothing 2a：Keybox 与 RKP 材料研究复核教程

中文 | [English](Tutorial_en.md)

本教程用于复核已有研究结论和证据关系。公开资料不包含设备专用补丁、固件、真实密钥或可直接执行的提取命令。完整机理见[本机型原理](../03_原理/原理_zh-CN.md)，历史过程见[实践记录](../02_流水记录/流水记录_zh-CN.md)。

## 1. 先固定研究对象

记录设备型号、系统构建、KeyMint HAL 和 Trustonic Trustlet 版本，以及启动链状态。版本、槽位和输入哈希必须属于同一轮实验。不同固件版本中的偏移、TA 布局和容器长度不能互换。

将结果分为两类：一类是 Factory Keybox 中的 EC/RSA 密钥及证书链；另一类是与 rkp_bcc_km 路径相关的派生材料。二者来源、用途和验收方法不同。不能用某一类结果证明另一类成功。

## 2. Keybox 路线的研究顺序

1. 先观察未修改环境中的 KeyMint 调用与设备证明输出，保留失败码和调用日志。
2. 将普通世界的 KeyMint HAL 请求与 TEE 中的 Trustlet 命令、TCI 结构和映射缓冲区对应起来。
3. 区分安全对象的密文、解密后短暂存在的明文，以及客户端能够读取的共享缓冲区；只有第三者可能构成外流证据。
4. 比较未修改调用和受控诊断调用的返回长度、缓冲区边界与内容类型。客户端返回成功本身不证明获得了 Keybox。
5. 在主机侧解析长度前缀和 DER 条目，分别识别 EC 私钥、RSA 私钥、叶证书与上级证书。
6. 将每把私钥导出的公钥与相应叶证书的公钥比较，再检查证书链签名、根证书、用途和 Android attestation 扩展。
7. 将结果与同轮 KeyMint 证据核对，排除把随机密钥、自签证书或旧 RKP 池误判为 Factory Keybox。

## 3. RKP 派生材料路线

研究记录中的 32 字节材料来自特定 KeyMint/Trustlet 的 rkp_bcc_km 派生路径。复核时必须同时记录派生标签、输入来源、调用上下文、长度和同轮身份关系。不能仅因长度为 32 字节就称它是通用 UDS 根秘密，也不能将它与 Factory Keybox 私钥混同。

先保留原生 RKP 请求的对照，再检查研究材料是否在相同协议层级参与身份构造。主机产生的请求、设备签名、证书响应与新生成密钥之间必须形成同轮闭环。历史记录中的直接 CSR 失败与后来使用原生 Binder CSR 结构的成功属于不同分支，不能合并成一次顺利执行。

## 4. 验收表

| 检查对象 | 必要条件 |
|---|---|
| Keybox 格式 | 条目长度、DER 解析和 EC/RSA 类型一致 |
| 密钥关系 | 私钥导出的公钥等于对应叶证书公钥 |
| 证书链 | 逐级签名、用途、根证书与 attestation 扩展可核对 |
| RKP 身份 | 派生材料的层级、同轮请求与签名关系一致 |
| 结果来源 | 每个结论能追到具体版本、对照、日志和失败分支 |

任何一项缺失时，将状态标为“未证实”，不要以证书存在或单次返回成功代替全部验收。
