## 研究链路与结果验收

现有研究记录涉及启动链验证边界、受控研究环境、与版本匹配的 TEE/KeyMint 观察以及主机侧解析。Fenrir 是部分历史路线的研究基础；仓库名称和研究范围不限定于这一方案。它在这些记录中的角色是研究 MediaTek 启动链对后续组件的验证边界，使授权实验设备能够进入受控观察环境。这个边界属于引导流程，不等于普通应用获得权限；引导链能启动或具有 ADB/root，不能单独证明取得了 TEE 内部材料。

之后的研究要依赖与机型、系统构建及 TA/TEE 版本相匹配的诊断路径，分别解释 Keybox 处理、RKP/DICE 派生关系与证书签发。Fenrir 本身不生成厂商签名或 Google 证书；出现一份证书，也不能证明取得了底层 seed。三台设备的具体差异、失败路径和证书关系见上方详细原理报告。

来源记录中的结果至少需要独立核对以下关系，且这些门槛**不表示公开副本已通过人工复验**：

- **目标与输入**：型号、构建、槽位和相关组件对应同一实验；输入文件与记录的哈希相符。
- **运行环境**：启动状态、TEE/KeyMint 服务和观察能力与记录一致。
- **结果结构**：长度、编码、容器字段和解析结果符合该类材料的预期；示例或模拟值不得混作实测值。
- **密钥与证书**：公钥、证书链、签发关系及 RKP/CDI 关系由同轮证据相互印证。
- **来源与公开边界**：结论可追溯到输入、流水和验证证据；公开文件不包含可复用秘密或设备唯一身份材料。

任何关系不符时，应保留失败证据并标明未验收，不得通过修改记录制造通过结果。若这份原理整理对你的研究有帮助，欢迎通过下方公开渠道捐款支持后续维护。
